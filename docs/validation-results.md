## Encoding (Clang integrated assembler and LLD)

Programs are assembled and linked at the code base address; the bytes of the `.text` section must equal the bytes produced by this tool.
A pseudoinstruction program whose bytes differ is compared line by line. Clang assembles each line for the address that the line has in this tool's program, and its bytes of the whole text must be its bytes of the lines in source order. ## Decoding (reassembly by Clang, disassembly by Capstone)

Random 32-bit words (fixed-length targets) or random 15-byte strings (x86-64) are decoded. Accepted encodings are reassembled from the decoded text and must give the same bytes, or bytes that Capstone disassembles to the same instruction; Capstone must name the same instruction.
On x86-64, a relative branch or call whose reassembled bytes differ is assembled again at its original address, where earlier instructions of different length cannot move it, and counts as identical when Clang then gives the original bytes.
Rejections are checked in two ways: an encoding rejected as invalid must not be an implemented instruction in Capstone, where the implemented instructions are Capstone's names for the encodings of the instruction sweeps; and for every rejected encoding that Capstone decodes, this tool's own assembler must not produce those bytes from Capstone's text, including the short form of a jump.
A rejection as unsupported that Capstone does not decode cannot be checked in either way. These rejections are counted in a column of their own; where the target entry of the harness states which of them are defined encodings, any other one is a failure.

## Exclusions and documented differences

### riscv

- Decoding: 1 encoding(s) accepted by Capstone but not by this tool: shift-immediate encoding with shamt[5] = 1, reserved in RV32I and defined only in RV64I.

### mips

- Execution: 86 case(s) compared in every respect that this reason does not affect: jr or jalr to an address with bit 0 set: the profile has neither MIPS16e nor microMIPS, so the address is kept and the Address Error exception belongs to the fetch of the target; Unicorn 2.1.4 treats bit 0 as the instruction-set mode bit and clears it.
- Execution: 55 case(s) compared in every respect that this reason does not affect: jr or jalr to an address below 0xC0000000 with bit 1 set and bit 0 clear: the Address Error exception belongs to the fetch of the target; the Linux build of Unicorn 2.1.4 reports that fetch as UC_ERR_READ_UNALIGNED before the jump completes, while the Windows build completes the jump.
- Execution: 40 case(s) compared in every respect that this reason does not affect: jr or jalr to an address in 0xC0000000 to 0xFFFFFFFF: Unicorn 2.1.4 translates these kernel segments through its TLB model and reports the failed fetch of the target as UC_ERR_READ_UNMAPPED, which the harness cannot tell apart from a fault of the jump itself.
